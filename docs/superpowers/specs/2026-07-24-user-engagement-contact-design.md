# 华韵非遗用户互动与联系功能设计

日期：2026-07-24

## 1. 目标

在不改变现有首页视觉、非遗图片、视频、CMS 内容、飞书同步和数据接口的前提下，让注册和登录产生清晰价值：

- 收藏喜欢的非遗项目
- 保存并查看浏览记录
- 登录后点赞非遗项目
- 登录后发表评论，审核通过后公开
- 访客或登录用户提交联系、传承支持和合作申请
- 管理员在现有后台审核评论并处理申请

## 2. 已有能力

项目已经具备以下能力，本次直接复用：

- Supabase 用户注册、登录和会话
- `user_favorites` 收藏数据与详情页收藏按钮
- `user_browsing_history` 浏览记录及详情页自动记录
- `/[locale]/profile` 个人中心，可展示收藏和浏览记录
- 现有管理后台身份校验与管理接口模式
- 中英文路由和文案结构

本次不会重建收藏和浏览记录，只补足入口、反馈状态和个人中心导航。

## 3. 页面与交互

### 3.1 顶部导航

- 用户未登录时保留“注册”和“登录”。
- 用户登录后将这两个入口合并为“个人中心”。
- 个人中心入口显示收藏与浏览记录，不改变其他导航项。

### 3.2 非遗详情页互动区

现有主图、视频、标题、正文和 CMS 内容保持不变。只在现有内容层中增加：

- 收藏按钮：复用现有 `FavoriteButton`。
- 点赞按钮：显示总点赞数；登录后可点赞或取消；同一账号对同一项目只能点赞一次。
- “成为传承支持者”按钮：打开统一在线申请表单，并预选“传承支持”。
- 评论区：登录用户可提交评论；提交后显示“等待审核”；公开区只展示审核通过的评论。
- 未登录用户点击点赞、评论时跳转登录页，登录后可返回原详情页。

### 3.3 个人中心

个人中心采用清晰的分区或标签：

- 我的收藏
- 浏览记录
- 我的评论及审核状态
- 我的支持与合作申请及处理状态

继续保留现有语言偏好、兴趣标签和推荐能力。现有个人中心数据不迁移、不删除。

### 3.4 联系我们

首页“联系我们”不再跳转到非遗项目列表，而是在首页展示完整在线表单，或跳转到独立联系区锚点。

表单字段：

- 姓名，必填
- 邮箱，必填
- 联系类型，必填：普通咨询、成为传承支持者、项目合作、内容授权
- 机构，选填
- 关联非遗项目，按入口自动带入，选填
- 留言，必填
- 隐私说明确认，必填

访客可以提交。登录用户提交时自动关联账号，但页面不公开邮箱或电话。

### 3.5 管理后台

在现有管理后台增加两个工作区：

- 评论审核：查看待审核评论、关联项目、提交时间；执行通过或驳回。
- 联系申请：按类型和状态筛选；查看联系信息与留言；状态可设为新提交、处理中、已完成。

后台操作继续使用现有管理员会话校验，不开放给普通用户。

## 4. 数据设计

### 4.1 `heritage_likes`

- `id`
- `user_id`
- `heritage_item_id`
- `created_at`
- 唯一约束：`user_id + heritage_item_id`

用户只能管理自己的点赞。公开页面通过受控查询读取项目点赞总数，不公开用户列表。

### 4.2 `heritage_comments`

- `id`
- `heritage_item_id`
- `user_id`
- `body`
- `status`：`pending | approved | rejected`
- `created_at`
- `updated_at`
- `moderated_at`

用户只能新增评论、查看自己的评论状态，不能自行批准。公开页面只读取 `approved` 评论。评论正文限制长度并进行纯文本处理。

### 4.3 `contact_submissions`

- `id`
- `user_id`，访客时为空
- `heritage_item_id`，无关联项目时为空
- `kind`：`general | supporter | cooperation | licensing`
- `name`
- `email`
- `organization`
- `message`
- `status`：`new | in_progress | resolved`
- `created_at`
- `updated_at`

公开端不直接写数据库，而是通过服务端接口校验和提交。管理员可读取和更新状态。

## 5. 安全与错误处理

- 点赞和评论必须使用真实登录会话。
- 评论默认状态始终为 `pending`，客户端不能指定审核状态。
- 联系表单进行邮箱格式、必填项、长度和提交频率校验。
- 联系提交增加隐藏防机器人字段，并在服务端拒绝异常重复请求。
- 所有用户数据表启用 RLS；管理员操作继续经过现有后台认证。
- 提交成功、等待审核、失败和重复提交均提供中英文可见反馈。
- 不在公开页面或客户端暴露管理员密钥、服务角色密钥和联系申请数据。

## 6. 组件边界

- `HeritageEngagementBar`：组合收藏、点赞和支持入口。
- `HeritageLikeButton`：点赞状态、计数和登录引导。
- `HeritageComments`：公开评论、用户提交和审核状态。
- `ContactApplicationForm`：首页联系及详情页支持/合作申请共用表单。
- `ProfileDashboard`：扩展评论与申请状态，不复制收藏和历史逻辑。
- 管理后台客户端组件：评论审核和申请处理各自独立。
- 数据访问层：点赞、评论、联系申请分别使用独立 repository/service，避免影响 CMS 和飞书同步仓储。

## 7. 数据流

1. 详情页服务端读取公开项目内容、点赞总数和已通过评论。
2. 客户端读取当前用户的收藏、点赞和本人评论状态。
3. 点赞使用登录会话写入或删除唯一点赞记录。
4. 评论提交后写入 `pending`，管理员批准后才进入公开查询。
5. 联系表单通过服务端接口写入申请，访客无需登录。
6. 管理员在后台更新评论或申请状态，公开页面和个人中心随后读取最新状态。

## 8. 测试与验收

- 未登录用户点击点赞或评论会进入登录流程。
- 登录用户可点赞、取消点赞，刷新后状态和计数正确。
- 同一用户无法产生重复点赞。
- 评论提交后只对本人显示“等待审核”，公开页面不可见。
- 管理员批准后评论公开，驳回后不公开。
- 收藏和浏览记录继续正常显示在个人中心。
- 访客可提交联系表单；无效邮箱、空留言和高频提交被拒绝。
- 管理员可筛选、查看和更新联系申请状态。
- 中文和英文页面文案完整。
- 手机和桌面端无重叠、溢出或布局跳动。
- 运行类型检查、相关单元测试、完整测试和生产构建。

## 9. 明确不修改

- 不替换或编辑任何现有非遗图片、视频、标题、正文和项目数据。
- 不改变首页已确认的 Hero 与主要视觉结构。
- 不改变 CMS、飞书同步、媒体上传和现有内容 API 的行为。
- 不删除现有 Vercel、Supabase 或域名配置。
- 不公开邮箱和电话。
- 不允许评论未经审核直接发布。

## 10. 实施顺序

1. 验证并显性化现有收藏、浏览记录和个人中心入口。
2. 新增点赞数据、接口和详情页按钮。
3. 新增评论数据、提交、公开展示和后台审核。
4. 新增统一联系/支持/合作表单及后台处理。
5. 完成中英文、移动端、权限、测试和生产构建验收。
