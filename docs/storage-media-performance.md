# Storage Media Performance

This document describes the production media pipeline for HuaYun ICH.

## Storage Configuration

- Bucket: `heritage-media`
- Visibility: public read
- Max object size: `524288000` bytes
- Allowed image types: `image/jpeg`, `image/png`, `image/webp`
- Allowed video types: `video/mp4`, `video/quicktime`, `video/webm`
- Migration: `supabase/migrations/20260607_media_performance_storage.sql`

Run the migration before using CMS uploads in production. The migration updates the bucket allow list and recreates the public read policy for Storage objects in this bucket.

## CDN Cache Policy

All CMS-managed objects are written with immutable-style cache metadata because generated paths include a timestamp and uploads use `upsert: false`.

- Images and thumbnails use `cacheControl: 31536000`.
- Videos and video posters use `cacheControl: 31536000`.
- Keep replacing media by uploading a new object, then updating the database reference. Do not overwrite existing objects.

Supabase serves public Storage objects through its CDN. Next Image is configured to accept `**.supabase.co/storage/v1/object/public/**` and can emit AVIF or WebP for rendered images.

## Image Upload Flow

1. Admin selects or drags JPG, PNG or WEBP images in `/admin/media` or the heritage edit media panel.
2. The browser decodes the source image with Canvas.
3. The main asset is resized to a max dimension of `2200`.
4. The thumbnail is resized to a max dimension of `480`.
5. Both outputs are encoded as WebP before upload.
6. The upload API writes the main image and thumbnail to Supabase Storage with long-lived CDN cache metadata.
7. The API inserts the media metadata into `heritage_media`.

The source file name is stored as `original_file_name`; the optimized WebP file name is used for Storage delivery.

## Video Upload Flow

1. Admin selects or drags MP4 or MOV files.
2. The browser reads video metadata and captures a poster frame.
3. The poster frame is encoded as WebP.
4. The video is uploaded through TUS resumable upload with `6 MB` chunks.
5. The poster is uploaded through the same TUS path.
6. TUS metadata includes content type and `cacheControl: 31536000`.
7. The CMS registers the final public URLs in `heritage_media`.

## Video Streaming

The detail page uses native HTML video with `preload="metadata"`, controls, poster images and Supabase public Storage URLs. Supabase Storage supports HTTP Range requests for public objects, so MP4 and MOV playback can stream progressively without downloading the full file before playback.

For best production playback:

- Use MP4/H.264/AAC for broad browser support.
- Keep MOV for admin ingestion or archival uploads, but prefer MP4 for public-facing main video.
- Avoid replacing objects in place; upload a new file path so CDN caches stay predictable.

## Operational Checks

- Verify bucket MIME types include `video/quicktime` before testing MOV uploads.
- Verify uploaded images end with `.webp`.
- Verify Storage response headers include a long `Cache-Control` max age.
- Verify video requests in the browser Network panel use `Range` after seeking.
- Keep `NEXT_PUBLIC_SUPABASE_URL` set so public Storage URLs can be generated by the upload panel.
